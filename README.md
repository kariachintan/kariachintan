# 💫 About Me:
🔭 I’m a Director of Software Engineering who still ships code. I build practical AI products, developer-productivity tooling, and web platforms that stay up, and I lead the teams that run them.<br><br>🧭 I built **decision-guide**, an explainable decision assistant: a deterministic engine filters by needs and budget, ranks with every score visible, and answers follow-up questions grounded in the catalog. A model may only phrase what the engine has evidence for.<br><br>🛡️ I’m turning “can an agent do this?” into “can we trust it to?” **agent-reliability-lab** runs seven fault-injection scenarios (tool failures, hangs, fabricated claims, runaway budgets, session isolation) against a tool-using agent loop and reports what actually happened.<br><br>👯 I’m looking to collaborate on AI agents, RAG systems, and developer tools that earn their place in someone’s workflow.<br><br>🌱 I’m currently learning how to give AI more autonomy without giving engineering less sleep.<br><br>💬 Ask me about engineering leadership, shipping AI products, scaling web platforms, and untangling “just a small change.”<br><br>⚡ Fun fact: My favorite performance optimization is deleting an unnecessary meeting.

# 🚀 Projects:
| Repo | What it shows |
|---|---|
| [decision-guide](https://github.com/kariachintan/decision-guide) | Explainable recommendations over a synthetic catalog. Needs-and-budget filtering, inspectable scoring, side-by-side comparison, and grounded conversational follow-up with a guard that catches invented items. |
| [agent-reliability-lab](https://github.com/kariachintan/agent-reliability-lab) | Fault-injection playground for AI agents: retries, timeouts, circuit breaker, budgets, session isolation, and claim checking, with a generated scenario report. |
| [ticket-readiness-lab](https://github.com/kariachintan/ticket-readiness-lab) | Advisory review of engineering tickets for missing acceptance criteria, ambiguity, edge cases, and dependencies. Separates facts from assumptions; a human decides. |

All three: Python with no required dependencies, tests and CI, runnable with no API key. Synthetic data throughout; personal projects, not employer work.

## 🧠 How I think about AI products:
- The model proposes; deterministic code disposes. Ranking, budgets, and claim checks live outside the model.
- “Degraded” is a valid status. An honest “I couldn’t” beats a confident guess.
- Facts and assumptions get different labels, in tools and in tickets.
